## 1. Fluxo sem microscópio

| Situação | Comportamento |
|---|---|
| Abriu sem microscópio, com outra(s) câmera(s) | A página **"Procurando microscópio…"** ganha na descrição a dica "Você também pode usar outra câmera pelo menu ☰ → Câmera." — a escolha é sempre pelo menu |
| Abriu sem câmera nenhuma | StatusPage "Procurando microscópio…" (como antes) |
| Microscópio plugado antes de qualquer escolha | Abre sozinho (Auto, inalterado) |
| Outra câmera em uso + microscópio plugado | **Não troca.** Toast "Microscópio conectado" com ação **"Usar"** — 1 toast por transição (re-arma ao desconectar) |
| Gravação em andamento | Troca de câmera bloqueada (toast "Pare a gravação…") — inclui o "Usar" do toast |
| Reabrir o app | A escolha manual **não persiste**: a prioridade volta ao microscópio |

Implementação: `CameraService::offers_alternatives()` (função pura
`offers_alternatives_for`, testada sem GTK), `microscope_id()`,
`active_is_microscope()`, `active_dev_node()`; a dica vai na
descrição da `searching_page` via `searching_description()` (pura,
testada).

**Correção pós-teste físico:** a página separada "Microscópio não
encontrado" nunca aparecia — `on_state_change()` só rodava em
eventos de câmera e, sem microscópio nem hotplug, nenhum evento
chega (a stack ficava no filho padrão). Duas revisões depois
(botão → texto), a solução é: `on_state_change()` agora roda uma
vez no `post_view`, então página e descrição iniciais refletem a
enumeração real sem depender de evento. Testado neste notebook com
o microscópio desconectado: `alternatives=true` e a descrição logada
exibe o texto combinado — "Conecte o microscópio a uma porta USB.
Você também pode usar outra câmera pelo menu ☰ → Câmera."

## 3. Formatos de outras câmeras

`modes_from_caps` agora lê também `image/jpeg` (fourcc `MJPG`); o
pipeline insere `jpegdec` só nesses modos (`plugins-good`, já em
`Depends`). `select_default_mode` (pura, testada):

1. **YUY2/raw ≤1280×720 @ ≥25 fps** (menor área vence — mais fps);
2. **MJPG ≤1280×720 @ ≥25 fps**;
3. YUY2 qualquer tamanho ≥25fps; 4. MJPG qualquer; 5. menor modo que
   exista (câmera lenta exótica). **Nunca acima de 720p por padrão**
   enquanto houver modo menor. `best_frame_rate` prefere ≤30 fps.

Na webcam ACER real (`/dev/video2`): 6 modos (YUY2 720p@10, 480p@30,
360p@30; MJPG 720p@30, 480p@30, 360p@30) → escolhido **YUY2
640×480@30**. Cadeias `v4l2src → YUY2` e `v4l2src → jpegdec`
testadas com PipeWire ativo — frames entregues.

O descarte de 3 quadros iniciais vale para qualquer dispositivo
(código inalterado).

## 4. Por dispositivo (chave `VID:PID` ou id estável)

| Recurso | Estado |
|---|---|
| Brilho/contraste (§6.11) | Já era por dispositivo (`adjust_key_for`) — confirmado, inalterado |
| Calibração (§6.9) | **Nova:** `CalibrationProfile.device` + `active_calibrations{device→name}`; combo mostra só perfis da câmera ativa; sem perfil → medidas em px + aviso **"Sem calibração para esta câmera"**; a do microscópio **nunca** aplica a outra câmera |
| Migração | Config v1.0 (`active_calibration` global + perfis sem `device`) → tudo migrado para `05e3:f12a` no `load_config` (round-trip testado) |
| Resolução da foto | "Nativa" = tamanho real do frame da câmera; interpoladas (2×/2,5×) só aparecem se o resultado couber em **1600×1200** — regra que coincide com os tamanhos do microscópio. Preferência inválida cai para nativa |
| Botão Snap | Inalterado — atua na câmera ativa; `hiview-buttond` intocado |

`select_default_mode` + `usb_device_key` compartilham a mesma regra
`VID:PID`→`stable_id` já usada pelos ajustes.
